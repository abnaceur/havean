# S06 — consented scoped analytics and redacted audit

## Acceptance and minimum evidence

Six declared event kinds are projected from transactional outbox source IDs into
an immutable metadata-only ledger and bounded async worker daily counters. Source
IDs and opaque dedup keys are unique. Impression/view/save keys count one consenting
account/property/UTC day; committed inquiry/booking/quote keys count each request
once. Same receipts and repeated source events cannot inflate counters. Projection
locks pending rows, updates the count and marks the source atomically; two competing
worker batches and a subsequent replay preserve exact counts. Category/city snapshots
include explicit agent/provider inquiry mappings and do not establish availability.
Unknown private message/document kinds do not enter analytics. No historical opt-in
or event counts are inferred before activation. Optional signals are not a total
visitor count or cohort conversion probability.

Three Docker integration checks pass. The six-kind fixture yields [1,1,1,1,1,1]
from 6 unique source events, pending count becomes zero, retries/concurrent workers
preserve counts, resale/renovation filters isolate the right events, and direct
agent/provider inquiries increment their declared category exactly once. Real
consent/view/impression APIs and trusted transaction/source fixtures are labelled
separately; this test does not claim six native business admission journeys. A
private message/document/contact sentinel remains absent from report, CSV and audit
metadata. Raw ledger/counter edits are denied. Actual current administrator locks
are required for report/audit reads; forged labels and SQL projection/ledger reads
deny. Dates, ordered bounded periods, category/city and audit fields are validated.
Preference changes require the actual active owner, current version and changed
state; own preference is included in the existing private export port. False/stale
consent states deny optional impressions and future views. Two adjacent real HTTP
ranking regressions pass without score inflation or private/withdrawn projection.

The final production native desktop/mobile journeys pass with distinct real buyer
and administrator sessions/MFA: property navigation, durable opt-in and permitted
view, card impressions, city/category filters, live worker counts, real native CSV
download with exact safe scope/definitions, native action/resource audit search,
viewport/axe checks, durable withdrawal and immediate 403 for stale impression
requests and non-admin reports. Earlier aggregate counts remain as disclosed.
Serious/critical axe violations are zero; tested viewport bounds pass. Synthetic
private auth traces are excluded and approved local baselines are preserved.

Initial generation omitted new schema imports and then binary export annotation;
final 316 canonical operations/OpenAPI pass. Initial fixture inserts omitted a
RETURNING ID, administrator actor context, and quote organization; those setup
failures were fixed without weakening source guards. Applied SQL 156 exposed an
ambiguous `subject` variable; forward SQL 157 corrects it. Forward SQL 158 explicitly
maps agent/provider scopes; older profiles with unknown market are not assigned an
invented one, so this coverage uses labelled scoped synthetic copies. Initial
checkbox checks found a pending-state reversion; the native pending choice is now
visible while recording still waits for saved API consent. The next browser run
found CSV was incorrectly sent through API JSON response validation; the binary
export whitelist is fixed. Final runs after that and after scope expansion pass.
Initial failed logs are retained, not counted as successes.
