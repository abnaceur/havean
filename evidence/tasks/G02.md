# G02 — Communities, buildings and private unit separation

Migration 015 adds community neighborhood relationships, approximate geography administration, building facts and optional unit/building association. Database triggers reject community/neighborhood and unit/building parent mismatches. Private unit addresses remain in the dedicated protected table and never appear in public community/building DTOs.

Community/building create, edit and archive run through the same role/version/state/audit administration service. Public building reads whitelist ID, stable slug, name, floor count and completion year; community responses use approximate coordinates rounded to three decimals. Fixture seeding creates two buildings per community with deterministic identifiers and retains existing edits.

Evidence: `geography-database-tests.log` passes known public building reads, private sentinel absence and a real unit/building mismatch rejection. Desktop and mobile geography browser logs pass community building reads and invalid neighborhood-parent rejection. All workspaces typechecked after the model/controller/UI additions; the later city-routing work will extend community discovery and detail separately.
