# Q01 — public indexing and routing

## Acceptance and minimum evidence

Current API public eligibility produces bounded sitemap chunks and an index when
needed. Published details and active category routes are included; draft, paused,
archived, account/tenant/ops/API entries are excluded. Actual known timestamps are
used where available. API unavailability returns sitemap 503 with Retry-After.
English metadata, canonical public URLs and escaped WebPage/BreadcrumbList JSON-LD
use public facts only. Filtered/search/map/submission URLs are noindexed. Private
web routes and all ops routes have noindex metadata and response headers; robots
files exclude those paths. Current detail UUID/category aliases return 308 to their
canonical slug; withdrawn details return 404, without unrelated-offer redirects.

Two Docker/PostgreSQL integration checks pass: a trusted synthetic published fixture
is included while a draft is absent; pausing removes it and its public detail read
returns 404. No private source fields are serialized. Archived geography is absent.
Out-of-range chunks are empty and negative page inputs reject. These trusted SQL
fixtures validate eligibility, not an authoring journey.

Two final production Playwright HTTP checks pass under desktop/mobile projects,
using distinct synthetic fixtures and real Docker API/database/web/ops responses:
sitemap XML and actual public canonical metadata/structured data, UUID and wrong
category 308 redirects, filtered noindex, account/tenant/ops headers and metadata,
robots exclusions, followed by real withdrawal and HTTP 404 with noindex. This is
HTTP acceptance coverage, not an authenticated browser journey or new visual
baseline. Existing approved English visual baselines remain preserved.

The first and second runs found 200 streaming responses instead of 308. Redirects
are resolved with shared metadata and the global root loading boundary is removed;
existing consumer request loaders remain. This also allows actual withdrawal 404
before headers are flushed. Initial failed logs are retained and not counted as
success. Final production build verifies types after this correction.
