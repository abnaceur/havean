# F08 — generated API contract and canonical client (verified)

The controller schema extractor generates all 106 operations from their actual input validation expressions. Explicit response schemas cover public projections, private workspaces, money, pagination, files and redirects. Migrated database model generation exports schema definitions, never database values. The API validates requests and serializes responses through those same operation schemas; an invalid server response fails closed with a sanitized error. Public response parsing strips unlisted fields.

`packages/contracts/openapi.json` is generated from the canonical schemas and published at `/api/v1/openapi.json`. The generated typed `sdk` and existing component calls use one session-aware HTTP transport, with typed request/response validation, binary transfers, decimal strings and structured `ApiError` details. Request IDs are generated by the API, forwarded by both BFFs, and generated locally for BFF rejection/unavailability errors. Generic parser failures and workflow conflicts have stable sanitized codes.

Evidence: `evidence/api-contract-tests.log` records five real API checks: exact published/generated contract equality, generated client inventory reads with decimal strings and privacy checks, invalid range field errors and matching request IDs, typed authentication failures, and malformed JSON sanitization. `pnpm contracts:check` also rejects stale generated operation, SDK and OpenAPI files. The broad browser regression exercised the response contracts; inquiry locking and duplicate fixture assertions found there were corrected and verified separately in `evidence/account-regression-tests.log`.
