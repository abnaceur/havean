# F07 — role and organization authorization (verified)

Private API operations resolve current, active memberships and restrict them to the selected authorized organization. Platform moderation/support/editor roles have no artificial agency membership. Professional actions require verified staff MFA. Resource guards enforce ownership, agent assignment, valid management grants and tenant links. The database transaction sets actor, organization, review, support, assignment and grant scope locally, then commits or rolls back before releasing the connection. Consumer, owner and tenant memberships do not establish organization-wide database scope.

Public response contracts whitelist published fields. Private addresses are stored separately in `unit_private_details`, with no anonymous policy. Owners, assigned agents, active tenants and current managers can read only their permitted details. Expired management grants remove lease, financial and address access. Private listing revisions compare their author to the qualified actor function. Public inquiry/booking locks use a narrow published-only destination function rather than granting consumer update access.

Evidence: `evidence/authorization-tests.log` records 15 real PostgreSQL checks, including foreign organization denial, pooled scope cleanup, anonymous/foreign private address denial, owner/assigned/current manager access, expired grant denial and private revision isolation. `evidence/account-regression-tests.log` records four desktop/mobile inquiry, viewing, message and tenant maintenance checks after the permission changes. Integrated browser permission checks additionally deny unrelated finance/lead operations and forged organization selection.
