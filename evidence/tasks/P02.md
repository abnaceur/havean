## Exact acceptance and minimum tests

Twenty-seven checks pass in the isolated `haven-p02` Docker PostgreSQL stack
(`evidence/p02-integration-final.log`): four P02, five P01, three privacy and fifteen
database regressions. Real managers invite only current granted properties using
current grant versions. Exact verified recipients accept/decline; idempotent retry
creates one tenant/account link and acceptance event. Linked tenants read their own
whitelisted profile. Other accounts cannot enumerate or guess that profile or
invitation. Actual foreign managers and forged roles cannot link a foreign grant.

revoked owner authority and direct account-link forgery are denied. A private unit
without a published listing exposes its bounded community context to the exact
recipient. Decisions/history remain recorded. No management staff role is assigned.

Two desktop/mobile native P02 journeys pass (`evidence/p02-browser.log`): manager
invitation creation with lost acknowledgement/retry, verified tenant acceptance
with lost acknowledgement/retry, own profile access, retained timeline, manager
refresh and another account's guessed-profile/invitation denial. Axe serious/critical
and viewport checks pass. New screenshots are provisional local evidence.

Final lint/types/contracts/task gates and all production builds pass
(`evidence/p02-gates.log`, `evidence/p02-build.log`). SQL 110–112 applied in
development and the separate P02 test stack; existing approved baseline bytes
are preserved. Shared integration stack restarts were avoided after detecting
concurrent work.
