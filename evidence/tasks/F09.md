# F09 — transactional outbox and replay safety (verified)

Business writes and outbox events commit in one transaction. Stable queue job IDs, bounded exponential retries, recoverable dispatch and an event effect ledger prevent repeated platform effects. Workers lock both event and aggregate across processes. Search updates read the current published database projection rather than old event payloads and retain source-version tombstones for withdrawal. Notifications have a unique source event and commit atomically with event completion.

Idempotency keys are scoped to actor and hash method, route, selected organization and canonicalized payload. Equivalent object key ordering replays the original result; changed payloads or scopes return a conflict. The development Mailpit adapter reconciles SMTP delivery by stable Message-ID after a crash. Production email adapters must provide equivalent idempotent delivery; local Mailpit tests do not establish production provider delivery.

Evidence: `evidence/outbox-tests.log` records real BullMQ/Valkey tests that kill a separate worker with SIGKILL after SMTP delivery, restart processing and replay the event, leaving one email, one notification and one effect. A failed search projection retries an old publish event after withdrawal and verifies the search document remains absent with a newer tombstone. `evidence/idempotency-tests.log` records desktop/mobile real identity/API tests proving one saved search after replay and a 409 for changed data.

Mail adapter reconciliation follows [Mailpit's Message-ID search contract](https://mailpit.axllent.org/docs/usage/search-filters/).
