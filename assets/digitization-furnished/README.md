# Furnished property example (O/R/P/V)

O: Original authored objects in `furnishings.json`, generated by `scripts/demo/generate-furnishings.mjs`. The floor layout comes from `assets/digitization-coherent/layout.json`. No external furniture assets, photographs or textures are used.

R: The user requested a property-specific 3D model containing its contents. This fictional example contains 46 separate authored objects across five rooms: sofa, armchair, coffee and dining tables, chairs, beds, wardrobes, bedside tables, lights, curtains, cabinets, kitchen counter/hob, refrigerator, sinks, toilet, bath, shower fixture, rugs, plants, television and framed decor. Dimensions and placements are supplied, unverified inputs. They are not inferred measurements.

P: `tests/e2e/digitization-furnished-assets.spec.ts` renders the five 2048×1024 room panoramas and the interior photo directly from `property.glb`, using the exact object placements and camera coordinates in `cameras.json`. The panoramic renders add a ceiling and simple exterior background; the dollhouse model omits the ceiling to expose the interior. The original unrelated AI-generated room images are superseded for this property. The public tour uses the 2048-pixel processing tier, actual authored camera positions and doorway bearings.

P: The local published model is generated by the API from saved geometry and object inputs, then independently reviewed by a separate automated demo-role session through the ordinary model review/publication workflow. It is not a hard-coded browser overlay. The exported GLB contains 3D meshes with materials, and the viewer supports orbit, zoom and reversible wall clipping. Each panorama shows the same modeled furnishings. The model does not claim photorealistic surface detail.

V: This is a manually authored, synthetic furnished example. It demonstrates object authoring and consistent model/tour views; it does not validate automatic scene reconstruction, real-property accuracy, surveyed dimensions or human approval. The existing genuine-capture declaration is exercised only as a synthetic spherical fixture, as in the earlier example. GPU validation remains deferred and VR paused. No third-party models or new runtime dependencies were added.
