# CPU decoder isolation

The PDF/image runner is an authenticated internal service; the decoder is a separate bounded child. PostgreSQL and API-owned current-grant/lease checks remain workflow authority. This component does not authorize publishing, certify a deed or perform OCR.

Before uploaded bytes enter pypdf, PDFium or Pillow, `decoder_isolation.py` requires Linux x86-64 Landlock ABI >=6, sets no-new-privileges and disables dumpability. Its rules allow read-only runtime libraries, fonts and trusted processing code; only the current execution directory is writable. Signing keys must be mounted outside those readable roots and outside the execution root. Sibling executions, `/proc`, service credentials and arbitrary filesystem paths are denied. Landlock filesystem/network/scoped rules are paired with seccomp denying sockets, process creation/exec, cross-process inspection/signals, namespaces, mounts, io_uring and other bypass interfaces. No unsupported-host fallback runs an unconfined parser.

The existing supervisor still enforces CPU/address-space/file/output/deadline limits and terminates the child's process group on cancellation. Containers remain nonroot, read-only, capability-free and bounded. The authenticated HTTP parent does not enter the decoder sandbox: it must receive job-scoped bytes and record execution receipts. It has no infrastructure credentials or public ingress. Current local readiness exposes the actual Landlock ABI and isolation profile; execution stays disabled until explicit key/root configuration is supplied.

This allowlist is specific to tested PDF/image workloads. It deliberately disallows child threads/processes and outbound access. PaddleOCR, FFmpeg, COLMAP and GPU runtimes need separately reviewed/tested profiles rather than removing these restrictions globally.
