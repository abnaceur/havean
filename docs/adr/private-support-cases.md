# Private support cases and complaints

S01 support business rules live in the administration API. Consumers and operations
use the canonical typed session SDK. Creation has explicit version zero, reporter
consent, bounded validated English fields, optional published listing snapshot and
at most six owned scanned private photo/PDF attachments. Exact receipt keys retry
a committed request without duplicating case or public history.

Inventory owns public listing and media admission ports. A published listing read
locks its source without granting consumer UPDATE authority; supplied version must
match. Current active geography and actual source title/URL determine the snapshot.
Complaint creation never writes listing status. The recorded link/version remains
historical case context after future listing changes, with ordinary public routing
still responsible for the current listing's visibility.

Private media admission locks actual owned asset version, approved scan status,
private visibility and permitted photo/document purpose. Attachment bindings are
immutable and made only at root creation before its first history. Later file reads
recheck current case permission and actual exact approved/private asset version.
Image variants are served as WebP; PDFs retain the scanned original. Only internal
API code sees object keys. Session BFFs serve no-store bytes with nosniff/no-script
CSP; foreign actors cannot infer a file's contents through a guessed route.

Reporter reads include only their own cases and sanitized public history. Current
actual platform support/admin membership admits queue/detail/triage, independently
of supplied role labels. Identity admission locks active actor and staff membership;
triage also locks the active target assignee. A current root version and open-to-
triaged workflow are mandatory. Original reporter, description and source bindings
cannot be rewritten; public history is immutable and required in the same commit.
Historical cases keep explicit unknown original attribution instead of fake history.

The consumer entry supports published-property selection by human-readable title,
private uploads, retained failed inputs and receipt retries. Successful creation
replaces complaint context with a selected-case URL, so reload restores one case
rather than overlapping creation/detail dialogs. The operations screen exposes
current staff assignment and visible replies. Full escalation/resolution/internal
notes are the next ordered S02 task, not claimed as completed by S01.

O: original support entry observed in the supplied specification. R: no original
private case workflow retrieved. P: current scoped case creation, immutable public
context, actual private attachment admission and current support triage. V: original
private-flow parity, remote CI and production deployment remain unverified; the user
has deferred deployment and authorized pushes to main.
