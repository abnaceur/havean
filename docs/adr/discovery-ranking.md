# D06 version-1 ranking policy

Eligibility: current public/unexpired listings in the selected city/category, using the canonical typed filter compiler. Related listings must share city/transaction/segment and exclude their source. Development recommendations require on-sale/coming-soon public records in the selected city.

UTC windows: 7 days or 30 days including the current UTC day; metadata publishes start/end/as-of and rule version. Score is freshness (max 30 minus UTC calendar dates since publication, floor at zero; unknown publication dates get zero) + 2 × min(1000, unique consented account/day listing views in the window) + active curated boost (0–100). Sort score descending, published timestamp descending and UUID ascending. Default recommendation uses 30 days; public popularity rankings use selectable 7/30 days. Every active sponsored boost is labeled Sponsored, even at zero boost points.

Signals count only signed-in users who explicitly consent. The score is not a count of all visits. Server derives the account from the authenticated session. An event UUID and one-account/listing/UTC-day unique key prevent duplicate inflation, including repeat events with changed UUID. No message text, address, document, raw IP or device fingerprint is collected. View writes validate the current published version, actor/session, CSRF, idempotency and eligibility. Public readers receive only bounded aggregate counts, never private signal identities. Consent false records no event.

Curated boosts are authored by editors/admins through versioned controls; target city/current publication, bounded score and interval must be validated. Audit and outbox commit atomically. Public aggregate read ports omit editor identities and return no data for unavailable properties. Expired or paused boosts do not affect scores. Curated feed/ranking public labeling describes the deterministic rule; no invented agent success metrics.

Tests: independently compute known fixture scores/order; duplicate same-event and changed-event daily repeat cannot increase count; no-consent is a no-op; stale/publication/role/city errors; private signal/boost identities never public; sponsored label and scope persists in browser; withdrawal excluded immediately. New default recommended sort must retain SQL authority and declare ranking SQL behavior rather than claim index order supports score.
