# Commercial facts and explicit price/area bases

Commercial drafts carry a dedicated canonical facts object: office/retail/warehouse, exact gross and usable decimal areas, explicit advertised/pricing area definition, total/per-area price basis, fit-out, optional floor/parking and recorded permitted uses. Gross/usable areas are positive and usable cannot exceed gross. Decimal amounts remain strings and PostgreSQL NUMERIC; no total is computed from an area. A per-area rental amount retains its explicit day/month/year period. Sale offers must have no rental billing period.

Draft create/edit requires the commercial object only for commercial listings. It uses existing authenticated actor, agency/owner/assignment scope, root version and draft/rejected workflow checks. Updates persist commercial facts and rental period atomically with the listing/version/audit. Shared draft UI records and restores the explicit fields; new commercial units do not ask for residential bedroom/living-room counts. Commercial schema errors are shown beside its fields. The shared rental-terms form remains residential.

The database separates sale_basis and rent_basis and rejects a basis for the wrong transaction. New authored rows require explicit area/use/price facts. Old stored sale basis values are preserved under sale_basis and cleared from rent_basis; prices and missing area definitions are never inferred. Existing incomplete records retain a private legacy_incomplete marker. Importing that state requires the database schema owner; correcting facts through the API clears it. Publication checks complete commercial facts, alongside existing approved photos, responsible agent and availability rules. Existing legacy public inventory is not retroactively presented as measured/complete.

C02 completes public business filters/cards, and C03 completes business detail and inquiry context. Current canonical unit area remains a separate recorded property fact; advertised gross/usable facts retain their declared definition. Recorded permitted uses are author-supplied facts, not a new licensing verification claim.

O: existing commercial category navigation. R: specification C01 attributes and transaction/billing/area requirements. P: local English authoring UI and synthetic decimal office offers. V: original commercial screen parity, actual measurements/permissions and real inventory. No new human baseline approval or production/provider verification is claimed.
