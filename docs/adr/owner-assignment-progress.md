# Owner assignment and safe progress

Inventory owns owner submissions, assignment, immutable progress and private review notes. The module registry corrects the old services entry to match the existing inventory controller. Only an independent authorized moderator/admin or active manager of the already owning agency can assign a submitted request. Assignment checks the current request version, current agent credentials/profile/membership and agency scope under a root lock. Publication requires an explicit current matching assignment; the previous global first-agent fallback is removed.

Assignment authority does not grant access to the full owner submission, contact data or evidence. Migration 069 replaces the broad agency row policy introduced in 068 with bounded SQL ports: a safe assignment queue and a versioned assignment command. These derive actor/organization authority from the server transaction and membership records, have fixed search paths, and expose no private payload. Consumers cannot assign/approve through direct SQL. Existing owner and reviewer reads retain their scopes. Reviewer evidence grants remain independent of agency assignment.

Historical rejection reasons move into `owner_submission_review_notes` without inventing a reviewer attribution. Future reasons are stored there with the actual reviewer; owner DTOs and exports omit them. Owners see submitted, assigned, approved or review-completed milestones with the assigned public agent name and UTC timestamp. No historic milestones are fabricated where there is no recorded transition.

A trigger records actual status/assignment changes in the same transaction as the root update and appends an outbox event. Its engagement-owned notification port creates one safe in-app transactional progress notice with a return link. The port is unavailable to application callers; only the owner-run trigger invokes it. Status text, agent name and request link are included; private reasons/contact/evidence are excluded. Optional saved-search email preferences are separate; this task makes no ownership-progress email-delivery claim.

O: original owner entry only. R: specification O04 assignment/progress/notification and private-note requirements. P: English assignment workspace, safe timeline and synthetic owner/reviewer/agency sessions. V: original private agency workflow, real legal authorization and new visual approval.
