# Capture multipart transport spike

The actual pinned SeaweedFS 4.46 adapter supports create/list/upload/complete/abort multipart operations. Eight MiB parts provide at most 256 parts for a 2 GiB clip. Capture uses private server-selected `capture/<uuid>` keys in haven-private. Signed UploadPart grants expire after ten minutes and bind the key/upload ID/part number/content length. A gateway PUT-only route preserves Host for SigV4 and streams to storage through existing web/ops entrypoints; no new storage host port, browser credentials, BFF buffering or ordinary timeout/CSRF bypass is introduced. Bucket/key reads and create/complete/list/abort are not exposed by that route. Browser receives a signed capability only after the future API checks current session, target, upload owner/state/version and quota.

Actual gateway round trip preserved one completed part across a new client/request, rejected declared-size mismatch before completion, completed a second part and verified the complete object using a streaming SHA-256 read with bounded bytes. An unsigned PUT was rejected by SeaweedFS. Explicit abort removed the pending multipart and never created an object. ETags are opaque adapter identifiers, not whole-object SHA-256. Checksums therefore require authoritative streaming verification; the implementation does not assume Amazon checksum behavior. Node fetch replaces a manually supplied Host when switching URL hosts, so the isolated network test uses a real HTTP request with the exact signed Host. A browser uses the configured external origin directly.

This spike does not enable capture creation/finalization in the product. HE-B02 persists constrained sessions and grants, HE-B03 verifies bytes/MIME/checksum into quarantine, HE-B04 scans/decodes outside SQL transactions and HE-K02 schedules expiry cleanup. The test exercises the cleanup primitive, not a completed retention scheduler. Real 2 GiB/concurrency throughput and cost limits remain unmeasured. Production requires a same-origin HTTPS gateway or an explicitly configured reachable HTTPS upload origin with verified CORS; no localhost URL is production configuration.
