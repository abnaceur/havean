# Saved collections and private browsing history

Saved homes use a left join to the current public listing projection. A removed or archived listing remains in the user's collection as an unavailable stub with its saved ID and generic English title. It has no detail link, price, photos, private address, archived title, or unpublished description. The user can remove it even though it is unavailable. No private listing join or persisted copy of withdrawn public facts is required.

Browsing history is a separate opt-in account collection, independent of public ranking signals. An absent settings row means disabled/version zero; reading never creates consent. Every preference, record, removal and clear requires the own collection version and serializes on its own user lock. A visit additionally requires a current published listing version. Row security and restrictive consent/public-availability policies protect inserts and updates. Collection changes and audit/outbox writes are atomic. Request-key replay does not repeat effects. Timestamps are ISO strings in both direct and replayed DTOs.

Keep the 100 most recently visited unique listing IDs, ordered by time and listing ID. Recording an existing listing moves it to the top; older entries beyond that bound are removed in the same transaction. Turning history off stops future recording and preserves the collection until the user removes or clears it. Removal and clear affect only the authenticated user's collection. Unavailable visits use the same public-only stub approach. History persists across devices and refresh; account routes remain excluded from indexing.

The default development retention is the bounded collection until explicit clear/removal or the account-retention workflow. Audit/outbox events retain actor, action, resource IDs and versions; clearing the browsing collection does not erase security audit history. Production retention policy and the later A06 workflow handle retained records separately. No credentials, messages, private addresses or identity documents are collected as visit content.

All account/history interface and internal rules are P. Prior public navigation is O and first-party listing capability vocabulary is R. Original account/history visual parity is V. A signed-in detail visit records only when the user has enabled this separate preference; repeated component effects for the same visit do not start another mutation.
