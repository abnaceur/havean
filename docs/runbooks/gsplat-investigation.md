## Local runtime and reproduction

1. `Dockerfile.gsplat-local` builds the exact gsplat1.5.3 source commit and pinned GLM submodule with the existing CUDA12.6.3 source-build toolchain, torch2.7.1+cu126 and SM75 native extension. Source archives are checksum checked. Build with `docker compose -p haven-gsplat-build -f compose.gsplat-build.yaml build --builder default`. Downloads live in ignored `.gsplat-build`; wheel hashes, package inventory and notices are retained. This local image is not a production distribution approval.
2. `sh dev-gsplat.sh` probes the actual GPU, resolves the built versioned image to its immutable local `sha256:` image ID, provisions a separate private signing key if absent, starts the resource-limited private GPU runner, preserves the existing CPU camera/OCR API overrides and registers exactly one device slot. It records the image reference in ignored `infra/generated/gsplat-runtime.env`. Registry deployments instead require an audited `registry/name@sha256:<digest>` reference. Never use floating tags or commit keys.
3. The runner has no public port. It mounts a dedicated execution volume and only its independent key. The child permits the exact source directory, immutable libraries and selected NVIDIA devices. CUDA needs read access to `/proc/devices` and `mmap_min_addr`, writes to its own task metadata and a scoped local UVM listener. Only AF_UNIX/SOCK_SEQPACKET|CLOEXEC sockets can be created; connect, accept, send/receive, IP sockets and new processes remain denied. The focused kernel-scope functional check verifies those boundaries. Output-directory freshness is checked before PyTorch imports create temporary files.

## Stopping and recovery

Cancel through the normal actor-scoped run action. The API persists cancellation before contacting the runner. The GPU reservation is released only after a matching stopped receipt; elapsed time alone never releases it. Retain runner origin/key configuration while stopping or deleting existing jobs even if the enable flag is removed. Deletion purges runner scratch and private objects through the existing cleanup workflow.

New database recovery proofs use version 7 and include `digitization_training_inputs` (48 tables); historic version 6 remains 47 tables.
